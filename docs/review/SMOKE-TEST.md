# 冒烟测试 · biliHoyoFairy

> 本文档分两部分：
> - **§1~§3 回归基线**：**与版本无关**，每次发版前都跑一遍。验证的是各模块之间的接线（seam）没断、原有功能没被搬坏。
> - **§4 本版新增/变更项**：只列**当前待发版本**引入的行为变更，按新行为验收。发版后这一节整节替换成下一版的——历史版本的变更项归 `CHANGELOG.md`，不在这里累积（否则这份清单会越长越没人跑）。

## 0. 前提

- 待测文件：仓库根目录 **`biliHoyoFairy.user.js`**（唯一、自包含、已内联全部模块）。
- 版本号以 `src/meta.js` 的 `@version` 为准（本文不写死版本号，避免文档与代码对不上）。下文出现 `<版本>` 处即指它。
- ⚠ 油猴会按 `@updateURL`（指向 **main**）自动更新。测试未发布的分支产物时，装完请**关掉这个脚本的自动更新**，否则过一阵会被 main 上的旧版悄悄覆盖，你测的就不是你以为的那份代码了。
- 测试期间**只开这一个 B 站屏蔽脚本**，关掉其它同类脚本，避免互相争抢 DOM。

## 1. 安装（覆盖现有版本）

**办法 A（推荐）复制粘贴覆盖：**
1. Cursor 里 `Cmd/Ctrl+P` 打开**仓库根**的 `biliHoyoFairy.user.js`（不是 `src/` 里的）。
2. `Cmd/Ctrl+A` 全选 → 复制。
3. 浏览器 → 油猴图标 → 管理面板 → 点开已装的「biliHoyoFairy」→「编辑器」标签 → 代码区全选删除 → 粘贴 → `Cmd/Ctrl+S` 保存。

**办法 B：** 资源管理器右键根目录 `biliHoyoFairy.user.js` → Download → 把下载的 `.user.js` 拖进浏览器 → 油猴「重新安装/覆盖」。

**确认装的是新包**：油猴编辑器里搜一下，能看到 `// src/constants.ts`、`// src/match/engine.ts` 这种**模块边界注释**，且头部 `@version` 与 `src/meta.js` 一致。

⚠ **装好后先把所有已打开的 B 站标签页刷新一遍**（包括你原本开着的）。它们还跑着旧代码、攥着升级前的旧配置快照，随便拦几个视频就会把新配置整份写回去——这不是新版的问题，是旧版拦不住的行为。

装好后打开 `https://www.bilibili.com/`（**无后缀首页**），F12 开控制台，按下面跑。

## 4. 本版新增/变更项（0.0.7 + 0.0.8，待发布）

> 详细缘由见 `CHANGELOG.md`。这里只写**怎么验**。

### 首屏与扫描时机

### 可解释性 / 误伤自愈

### 性能与耗时采样（0.0.8 新增）
- [ ] **批量删除不再卡顿**：某个名单加到几百上千条（可用「⬇ 从账号黑名单导回」快速凑出来）→ 批量管理 → 全选 → 删除所选。应当**几乎瞬时**完成，不出现页面冻结。旧版这里是逐条存盘+全页重扫，秒级卡死。
- [ ] ⚠ **「清空」真的清掉了**（本轮修的 bug）：某个名单点「清空」→ 确认 → **刷新页面**，规则必须还是空的（旧版会全都回来）；且清空后原本被这些规则拦掉的视频应立刻重新出现（旧版界面空了但还在拦）。
- [ ] **勾选不卡**：批量管理下连续点十几个 chip，每次点击应即时反应，不出现整列闪烁重建。
- [ ] **批量添加也不卡**（本轮补的另一半）：「黑名单 → 🎯 关键词」的输入框里一次粘贴几百个词（逗号或换行分隔）→ 点添加。应几乎瞬时，且开着调试模式时 `config.save` 只 +1。
- [ ] **评论滚到底仍被过滤**：播放页开评论过滤 + 一个必然命中的条件 → **一口气滚到评论区最底部**，最后加载出来的那批评论也应被折叠。这条验的是评论影子树的独立观察器（上一轮把它从卡片观察器里摘出去后一度没有东西接手）。
